# 03 - Chat API Reference

English | **[简体中文](../03_chat.md)**

This page is the complete API reference for `AIKitClient` ([src/AIKitClient.h](../../src/AIKitClient.h)), mostly in table form. Vendor presets and endpoints are covered in [02_vendors.md](02_vendors.md); an in-depth look at the two streaming read modes is in [04_streaming.md](04_streaming.md). Sections tagged `v1.2.0` are new in this release.

## Lifecycle (begin + setter style)

| Method | Description |
| --- | --- |
| `explicit AIKitClient(Print* log = nullptr)` | Construction takes the log output target (any `Print`/`Stream`, e.g. `&Serial`, `&Serial0`); pass `nullptr` for full silence. The log object must stay valid for the client's lifetime |
| `bool begin(AIKitVendor vendor, const char* apiKey)` | One call to onboard a built-in vendor preset (19 in total, see [02_vendors.md](02_vendors.md)). Can be called repeatedly to switch vendors; a model previously set with `setModel()` is reset to the new vendor's default on switch. Returns `false` on invalid arguments |
| `bool begin(AIKitVendor vendor, const String& apiKey)` | Same as above (`String` overload) |
| `bool beginCustom(host, port, path, useHttps, apiKey, defaultModel = nullptr)` | Connects to any OpenAI-compatible endpoint (self-built gateway / vLLM / Ollama / relay…); `defaultModel` may be null |
| `void end()` | Ends the current request/stream and releases the connection (**all configuration is kept** — you can chat again right away) |
| `bool isReady() const` | Whether the client is ready to issue a request (begun and fully configured) |

## Vendor / model

| Method | Description |
| --- | --- |
| `AIKitVendor vendor() const` | Current vendor enum (`AIKIT_CUSTOM` means a custom endpoint) |
| `const char* vendorName() const` | Human-readable vendor name |
| `const char* model() const` | Current model name |
| `void setModel(const char* model)` / `setModel(const String&)` | Switch models (overrides the preset default; available models per vendor in [02_vendors.md](02_vendors.md)) |

## Request parameter setters

Can be changed at any time; **takes effect on the next request**:

| Method | Description |
| --- | --- |
| `setSystemPrompt(sys)` / `setSystemPrompt(String)` | The system message, automatically prepended to every request; pass `nullptr`/`""` to clear. If your message array itself already starts with a system message it is skipped automatically (no duplication) |
| `clearSystemPrompt()` / `systemPrompt()` | Clear / read the current system prompt |
| `setTemperature(float t)` | Sampling temperature, 0–2; out-of-range values are treated as clearing the parameter |
| `setTopP(float p)` | Nucleus sampling, 0–1 |
| `setMaxTokens(int32_t v)` | Writes `max_tokens` into the request |
| `setMaxCompletionTokens(int32_t v)` | Writes `max_completion_tokens` (the current Moonshot / OpenAI convention; the old parameter is deprecated) |
| `setTimeouts(connectMs, tcpMs)` | Connect / read timeouts, defaults 10 s / 30 s (first bytes from reasoning models can take tens of seconds, hence the generous read timeout) |

## TLS

| Method | Description |
| --- | --- |
| `setInsecure(bool)` / `insecure()` | Switch to skip certificate validation, **default `true`** (so the library works out of the box without NTP / root certificates). In production, always pair it with `setCACert()` and turn it off! |
| `setCACert(const char* pem)` | Custom root CA (PEM text); the pointer must stay valid during requests. On ESP8266 the library lazily parses it into a `BearSSL::X509List` on first request and caches it |
| `setCACert_P(PGM_P pem)` | [ESP8266 only] For certificates stored in PROGMEM, e.g. `setCACert_P(PSTR("-----BEGIN CERTIFICATE-----..."))` |

## Custom HTTP headers

Sent with every request:

| Method | Description |
| --- | --- |
| `int addHeader(name, value, replace = true)` | `replace=true`: a same-name header is overwritten into a single line (can also override the library's default `Content-Type` / `Accept`); `replace=false`: appended as a duplicate line (multi-value header scenarios). Returns `AIKIT_OK` / `AIKIT_ERR_NULL_ARG` / `AIKIT_ERR_TOO_MANY` |
| `void removeHeader(name)` | Removes the named custom header |
| `void clearHeaders()` | Removes all custom headers |
| `size_t headerCount() const` | Current count (capacity cap `AIKIT_MAX_CUSTOM_HEADERS`, default 8) |

## Custom JSON fields

Merged into the final request JSON — **parameters without a dedicated setter** (`tools`, `response_format`, vendor thinking switches…) are all passed through here:

| Method | Description |
| --- | --- |
| `int addJsonField(key, jsonValue, replace = true)` | `jsonValue` must be **valid JSON value text** (number / quoted string / object / array / `true`…). `replace=true` overwrites a same-name field generated by the library (can rewrite `model`/`temperature`); `replace=false` only appends when the field is absent. Validity is checked at set time; invalid input returns `AIKIT_ERR_BAD_JSON` |
| `addJsonField(key, float / int32_t / bool, ...)` | Numeric / boolean convenience overloads |
| `int addJsonFieldString(key, strValue, replace = true)` | Plain-text convenience: automatically quoted and escaped (good for custom business fields) |
| `void removeJsonField(key)` / `clearJsonFields()` | Remove / clear |
| `size_t jsonFieldCount() const` | Current count (capacity cap `AIKIT_MAX_JSON_FIELDS`, default 12) |

```cpp
ai.addJsonField("top_p", "0.9");
ai.addJsonField("enable_thinking", "false");
ai.addJsonField("tools", "[{\"type\":\"function\",...}]");   // current pass-through usage for Tool Calls
```

## Logging

| Method | Description |
| --- | --- |
| `setLogLevel(AIKitLogLevel)` / `logLevel()` | Levels: `AIKIT_LOG_NONE` / `ERROR` / `WARN` / `INFO` / `DEBUG`. Defaults to `INFO` when a log target was given, `NONE` when `nullptr` |

## Non-streaming chat (blocks until the response completes)

| Method | Description |
| --- | --- |
| `int chat(userText, String& outContent)` | Single user message → reply body |
| `int chat(userText, AIKitChatResult& result)` | Single user message → full result (body / chain-of-thought / finish_reason / usage, see the struct below) |
| `int chat(messages, count, String& outContent)` | Multi-turn / custom roles (`const AIKitMessage*` array; the system message is auto-prepended by `setSystemPrompt`, or can be passed explicitly). Note that `AIKitMessage` stores pointers only — the strings you pass must stay valid until `chat()` returns |
| `int chat(messages, count, AIKitChatResult& result)` | Full-result version of the above |

`userText` / `messages` each have `const char*` and `String` overloads. **As of v1.2.0 there is also a set of `AIKitHistory` overloads** (automatic history bookkeeping), see below.

## Streaming entry points (details in [04_streaming.md](04_streaming.md))

| Method | Description |
| --- | --- |
| `void onDelta(cb)` | Incremental body callback `void(const char* delta, size_t len)` (undecoded UTF-8 bytes) |
| `void onReasoningDelta(cb)` | Incremental chain-of-thought callback for reasoning models (`reasoning_content`; never fires when absent) |
| `int chatStream(userText)` / `chatStream(messages, count)` | Streaming mode A: callback style |
| `int chatStreamTo(userText, AIKitStreamResponse&)` / `chatStreamTo(messages, count, resp)` | Streaming mode B: `Stream` line-by-line reading |

## v1.2.0: Token usage accounting

Streaming requests carry `stream_options.include_usage` by default (supported by all mainstream OpenAI-compatible vendors), which makes the final chunk include the `usage` field; non-streaming responses include it natively.

| Method | Description |
| --- | --- |
| `void setIncludeUsage(bool)` / `bool includeUsage()` | Whether streaming requests carry `stream_options.include_usage`, **default `true`**. If a vendor rejects it (400), the library automatically drops the field and resends once |
| `AIKitUsage totalUsage() const` | **Cumulative** usage over this client's lifetime (summed across requests, streaming and non-streaming alike) |
| `void resetTotalUsage()` | Zeroes the cumulative counters (e.g. for per-session / per-day accounting) |
| `AIKitUsage lastUsage() const` | Usage of the most recent request (recorded for streaming and non-streaming alike) |

The `AIKitUsage` struct: `promptTokens` / `completionTokens` / `totalTokens` (`int32_t`); `valid()` tells whether the server returned them (fields are -1 when absent).

## v1.2.0: Automatic retry on failure

| Method | Description |
| --- | --- |
| `void setRetry(maxRetries, baseDelayMs = 1000, maxDelayMs = 30000)` | Retries up to `maxRetries` times; waits `baseDelayMs` before the first retry, doubling each time (exponential backoff), capped at `maxDelayMs` |
| `void setRetryEnabled(bool)` / `bool retryEnabled()` | Master switch (on by default); `setRetryEnabled(false)` disables retrying entirely |
| `uint8_t retryCount() const` | Currently configured maximum retry count (default `AIKIT_DEFAULT_MAX_RETRIES` = 2) |
| `void onRetry(cb)` | Callback fired right before a retry: `void(uint8_t attempt, int lastErr)`; **`attempt` counts from 1**, `lastErr` is the previous error code. Use it for logging / blinking an LED / reporting |

**Trigger conditions** (any one of these, with the master switch on):

| Condition | Behavior |
| --- | --- |
| Connection / transport failure (`AIKIT_ERR_CONNECT`), timeout (`AIKIT_ERR_TIMEOUT`) | Normal retry |
| HTTP `429 / 500 / 502 / 503 / 504` | Normal retry (backoff is especially valuable on 429 rate limiting) |
| HTTP 400 with an error body mentioning `stream_options` / `include_usage` | Automatically disables `include_usage` and resends |
| Other errors (bad parameters / parse errors / 401 / 403…) | **No retry** — retrying would not help |

**Two safety boundaries**:

- A streaming request that has **already emitted deltas** (`onDelta` / `onReasoningDelta` fired) is never retried, to avoid duplicate output;
- Line-by-line reading mode (`chatStreamTo`) **never retries automatically** — queued lines cannot be undone.

## v1.2.0: Chat overloads with AIKitHistory

History management is covered in [06_history.md](06_history.md):

| Method | Description |
| --- | --- |
| `int chat(AIKitHistory& history, userText, String& outContent)` | Automatic flow: user message into history → request carrying the full history → on success the reply goes into history; **if the request fails, the user message is rolled back** (a failure while appending the reply only warns, it does not error) |
| `int chat(AIKitHistory& history, userText, AIKitChatResult& result)` | Full-result version of the above |
| `int chatStream(AIKitHistory& history, userText)` | User message into history → streaming request; **you must assemble the reply body yourself in `onDelta` and append it via `appendAssistant()`** (the library cannot recover the full body internally) |

## Status queries (call after a request finishes)

| Method | Description |
| --- | --- |
| `int lastStatusCode() const` | HTTP status code of the most recent request (0 = no response headers received) |
| `int lastTransportError() const` | Underlying StreamHTTPClient error code (`SHC_ERROR_*`, 0 = none; pair it with `StreamHTTPClient::errorToString()`) |
| `String lastErrorBody() const` | Response body excerpt kept on non-2xx (≤384 bytes by default, tunable via `AIKIT_ERRBODY_MAX`) |
| `const char* lastFinishReason() const` | `finish_reason` of the most recent request (`"stop"` / `"length"` / …), recorded for streaming and non-streaming alike |
| `AIKitUsage lastUsage() const` | Usage of the most recent request (see the v1.2.0 section above) |
| `bool streamActive() const` | Whether a stream is in flight (new chat* calls during that time return `AIKIT_ERR_BUSY`) |

## Result structs (AIKitTypes.h)

| Struct | Fields |
| --- | --- |
| `AIKitChatResult` | `content` (reply body), `reasoningContent` (chain-of-thought, empty when absent), `finishReason`, `usage` (`AIKitUsage`) |
| `AIKitMessage` | `{ const char* role; const char* content; }` — a lightweight pointer view, strings are not copied |
| `AIKitUsage` | `promptTokens` / `completionTokens` / `totalTokens` + `valid()` |

## Examples

**Token usage accounting** (excerpt from [examples/15_TokenUsage](../../examples/15_TokenUsage/15_TokenUsage.ino)):

```cpp
AIKitChatResult r1;
int err = ai.chat("Describe Arduino in one word", r1);
if (err == AIKIT_OK) {
  Serial.println("[Reply] " + r1.content);
  if (r1.usage.valid()) {
    Serial.printf("prompt=%d completion=%d total=%d\n",
                  r1.usage.promptTokens, r1.usage.completionTokens,
                  r1.usage.totalTokens);
  }
}

// Streaming: include_usage is on by default; read lastUsage() afterwards
ai.onDelta([](const char* delta, size_t len) { Serial.write(delta, len); });
err = ai.chatStream("Count to five, separated by commas");
if (err == AIKIT_OK) {
  AIKitUsage u = ai.lastUsage();     // usage carried by the final chunk
}

// Cumulative across requests
printUsage("TOTAL", ai.totalUsage());   // tokens of both requests are counted
ai.resetTotalUsage();                   // zero it when needed
```

**Automatic retry on failure** (excerpt from [examples/16_AutoRetry](../../examples/16_AutoRetry/16_AutoRetry.ino)):

```cpp
ai.setRetry(3, 1000, 8000);            // up to 3 retries, exponential backoff starting at 1 s, capped at 8 s

ai.onRetry([](uint8_t attempt, int lastErr) {
  Serial.printf("[Retry] attempt %u, last error %d (%s)\n",
                attempt, lastErr, aikitErrorToString(lastErr));
});

String reply;
int err = ai.chat("hello", reply);     // failures are retried automatically per policy
Serial.printf("final error: %d (%s)\n", err, aikitErrorToString(err));
```

The repository's `examples/` directory has the complete set (21 in total); the full error-code table is in [07_advanced.md](07_advanced.md).
